## 2024-05-24 - [Critical Authorization Bypass in Token Issuance]
**Vulnerability:** The LiveKit token issuance endpoint (`/api/livekit/token/route.ts`) allowed any user to join a room using the host's username. While it didn't grant publisher permissions without the secret, it still issued a valid JWT with the host's identity (`sub: username`). This allowed an attacker to take the token and use it on the moderation endpoint (`/api/livekit/moderate/route.ts`), which only verified that the token's identity matched the host's username, bypassing all authorization checks and granting full administrative control over the room.
**Learning:** Issuing a token with a privileged identity, even if some permissions (like publishing) are withheld, is a critical security risk. If downstream services or other endpoints rely on the token's identity (the `sub` claim) for authorization, an attacker can impersonate the privileged user.
**Prevention:** Always strongly authenticate identity claims before issuing a token. If a user requests a privileged username but fails authentication, the request must be rejected entirely (HTTP 403), rather than issuing a degraded token with the same identity.
